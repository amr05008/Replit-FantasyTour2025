## Active Redesign — React + Vite SPA (`web/`), 2026

A high-fidelity redesign lives in **`web/`** as a standalone React + Vite single-page app (the go-forward UI; the Streamlit app documented below is unchanged and still deployable). Built from the `design_handoff_tdf2026/` prototype.

- **Run:** `cd web && npm install && npm run dev` (http://localhost:5173)
- **Test:** `npm test` (Vitest, 37 passing) · `npm run e2e` (Playwright walkthrough)
- **Build/deploy:** `npm run build` → static `dist/`; deployed on **Vercel** (`tdf-fantasy-tracker.vercel.app`, Vercel root directory = `web`). Repo: `amr05008/tdf-fantasy-tracker`.
- **Architecture:** `lib/format.js` + `lib/selectors.js` (pure view-models) → thin presentational screens (`screens/*`); all data is read through the single `data/useLeagueData.js` seam. Six screens: Standings, Stage, Team, Races + Draft & RiderProfile sub-screens. Plain JSX, inline styles + CSS custom properties for per-race accent theming.
- **Real data is wired (for completed races).** `web/src/data/useLeagueData.js` fetches `web/public/data/<raceId>.json` per race, falling back to the bundled `sampleData.js`. `web/public/data/tdf-2025.json` is committed (generated by `scripts/generate_data.py`); the app **defaults to TDF 2025** and shows real standings. A **not-yet-started race** (status `Upcoming` in the `races` manifest, e.g. TDF 2026) renders an `Upcoming` notice instead of fake data — no fetch. The app is **Tour de France only** (Giro/Vuelta removed). **Do NOT reuse `api_client.py`'s fetch — procyclingstats is behind a Cloudflare challenge; only the `pcs_fetch` seam (cloudscraper) gets through; run `generate_data.py` from a residential network.** **Still deferred (live 2026):** latest-stage detection, daily GC snapshots for movement arrows (`move`/`d`), and a refresh cron. See `docs/superpowers/specs/2026-06-19-data-json-frontend-wire-design.md` and `2026-06-19-upcoming-race-callout-design.md`.
- **Spec & plan:** `docs/superpowers/specs/2026-06-18-sunshine-fantasy-tdf2026-redesign-design.md` and `docs/superpowers/plans/2026-06-18-sunshine-fantasy-tdf2026-redesign.md`.

## Roster Management + PCS Data Layer (`*.py` at repo root), 2026

A standalone, **Streamlit-free** Python pipeline for entering the offline draft and fetching/scoring live procyclingstats (PCS) data — the go-forward backend the Phase 2 `data.json` generator consumes. Built 2026-06-19; spec/plan: `docs/superpowers/specs/2026-06-19-roster-management-and-pcs-fetch-design.md` and `docs/superpowers/plans/2026-06-19-roster-management-and-pcs-fetch.md`.

- **Cloudflare (critical):** procyclingstats.com is behind a Cloudflare managed challenge that breaks the `procyclingstats` package's plain-HTTP fetch. **All PCS HTTP must go through `pcs_fetch.get_html(path)`** — the single seam (fresh cache → cloudscraper → Playwright → typed `PCSBlockedError`). `pcs_parse` injects that HTML into the package parsers via `Stage(url, html=..., update_html=False)`. Run from a residential network; datacenter IPs (Vercel/CI) are challenged hardest.
- **Modules:** `pcs_time` (pure H:MM:SS), `pcs_fetch` (the seam + `.pcs_cache/`), `pcs_parse` (incl. `parse_stage_details`), `scoring` (`compute_standings` + the frozen `format_for_app` teams contract matching `web/src/data/sampleData.js`), `roster_store` (effective-dated stints, Option B, 3-active invariant), `rider_resolver` (typed name → validated PCS slug), `nations` (country code → name), `generator.generate_standings`, `scripts/generate_data.py` (writes the full `web/public/data/<raceId>.json`; `build_race_data` is pure + reorders PCS `Lastname Firstname` names), `verify.py` (connectivity + TDF 2025 end-to-end proof + slug validation).
- **Rosters:** `data/rosters.json` → race → participant → list of stints `{slug, name, team, from_stage, to_stage?}`. Active at stage N = `from_stage ≤ N ≤ (to_stage or ∞)`. Mid-race injury swaps preserve history (close old stint at swap−1, open new at swap).
- **Enter a draft:** `python draft.py draft|swap|show|verify`, or the `/draft` skill (`.claude/skills/draft/`) for natural-language entry ("Aaron drafted Pogačar, Vingegaard, Evenepoel"). Both validate before saving; never hand-edit `data/rosters.json`.
- **Dev:** `. .venv/bin/activate && pytest` (29 passing, offline via committed HTML fixtures in `tests/fixtures/`). `python verify.py` runs the live proof.
- **Known open items:** DNF scoring drops a missing rider from the team total (lowers it → inflates rank); `generate_standings` returns a `warnings` list, but the league's DNF-penalty rule is undecided. No "latest completed stage" auto-detection yet. Resolver can't derive ø/å/ł names (paste `rider/<slug>`). Playwright tier is untested live.

## Legacy Streamlit app (repo root: `app.py`, `api_client.py`, `races_config.py`)

The original UI. Still deployable (`streamlit run app.py --server.port 5000`), but the React app in `web/` and the Python pipeline above are the go-forward path as of 2026-06. When touching the root files:

- **Scoring rule** (both UIs): a team's score is the sum of its riders' cumulative GC times, lower wins, DNF/DNS riders are marked and excluded. `scoring.compute_standings` is the current implementation; `api_client.calculate_team_time` is the legacy one.
- **Config:** `races_config.py` holds the legacy race metadata and rosters (`RACES`, `TEAM_ROSTERS`, `get_race_config()`, `get_team_rosters()`); `team_config.py` is only a backwards-compatibility shim over it. Live rosters are **not** edited here — they live in `data/rosters.json` via `draft.py` or the `/draft` skill (Roster Management above).
- **Fetching:** `api_client.py` calls procyclingstats over plain HTTP behind 5-minute `@st.cache_data` TTLs and is Cloudflare-blocked from most networks. Don't extend it; new fetches go through `pcs_fetch.get_html`.
- **UI:** three tabs (standings, stage-analysis Plotly charts, team riders), dark-only theme with the yellow-jersey leader treatment, CSS inline via `st.markdown(unsafe_allow_html=True)`, OG/Twitter meta in the HTML head. UI copy uses simple, everyday language (Aaron's preference, noted in `replit.md`).
- **History:** Google Sheets → PCS (2025-11-01), the multi-race build-out (2025-11-02), and the 2026-06 cut back to Tour de France only are recorded in `replit.md`; don't re-derive them from the code.
